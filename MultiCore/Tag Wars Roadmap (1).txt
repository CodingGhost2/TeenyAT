            │            │            │            │
    ┌───────▼──┐   ┌────▼────┐  ┌────▼────┐  ┌───▼─────┐
    │ CLIENT 1 │   │CLIENT 2 │  │CLIENT 3 │  │CLIENT N │
    │ (VM #1)  │   │ (VM #2) │  │ (VM #3) │  │ (VM #N) │
    ├──────────┤   ├─────────┤  ├─────────┤  ├─────────┤
    │ ChaseBot │   │ TeamBot │  │PatrolBot│  │CustomBot│
    │   .asm   │   │   .asm  │  │   .asm  │  │   .asm  │
    └──────────┘   └─────────┘  └─────────┘  └─────────┘
    
    Each client:
    • Runs in isolated VM
    • Queries server for world state
    • Sends action requests
    • Cannot directly access other clients
    • Cannot modify world directly


This is exactly like:
* Minecraft server + player clients
* Game server + bot clients (StarCraft, Dota AI)
* MUD/MOO server + player agents

2. Server Responsibilities (main.cpp)
2.1 World State Management
The server is the only authority on:
* Player positions (all 20 agents)
* Map layout (tiles, walls, goals)
* Game state (scores, timer, frozen players)
* Collision results
* Tag events
// Server maintains authoritative state
struct ServerState {
    Player players[20];              // All agent positions
    int level[40][30];               // Map tiles
    int redScore, blueScore;         // Scores
    int gameTimer;                   // Centiseconds remaining
    MessageBus messageBus;           // Inter-client messages
    
    // Dynamic map mutation
    int nextMapChange;               // Frames until map updates
    CellularAutomata mapGenerator;   // Map evolution logic
};


2.2 Client Management
struct ConnectedClient {
    teenyat vm;                  // Client's VM instance
    int clientID;                // Unique identifier (0-19)
    int teamID;                  // 0=Red, 1=Blue
    int cyclesPerFrame;          // CPU budget
    ClientState state;           // ACTIVE, FROZEN, DISCONNECTED
    
    // Request tracking
    tny_uword lastRequest;       // Last MMIO address accessed
    int requestCount;            // Requests this frame (rate limit)
};


std::vector<ConnectedClient> clients;


2.3 Request Processing Loop
void serverGameLoop() {
    while (!tigrClosed(screen)) {
        // 1. RECEIVE: Let each client send requests
        for (auto& client : clients) {
            if (client.state != ACTIVE) continue;
            
            // Give client CPU budget to compute decisions
            for (int i = 0; i < client.cyclesPerFrame; i++) {
                tny_clock(&client.vm);
            }
        }
        
        // 2. UPDATE: Server processes world state
        updatePhysics();           // Apply movement commands
        checkCollisions();         // Tag detection
        updateDynamicMap();        // Cellular automata step
        processMessages();         // Route inter-client messages
        updateTimer();             // Countdown
        
        // 3. RESPOND: Render world state
        renderWorld();
        tigrUpdate(screen);
    }
}

3. MMIO Protocol (Client ↔ Server Interface)
3.1 Design Philosophy
Server-Client Protocol Principles:
1. Server never pushes - Clients must query (pull model)
2. Requests are stateless - Each query is independent
3. Server validates all requests - No trust in client data
4. Rate limiting - Prevent client spam
5. Partial observability - Clients see limited world state
3.2 Client Query API (Request)
// === CLIENT IDENTITY ===

Server Validation Example:
// Client writes: MOVE_REQUEST = 2 (East)
// Server processes:


void handleMoveRequest(ConnectedClient& client, int direction) {
    if (client.state == FROZEN) return; // Reject: client is frozen
    
    direction = direction % 8; // Validate direction
    
    float newX = client.x + dx[direction] * MOVE_SPEED;
    float newY = client.y + dy[direction] * MOVE_SPEED;
    
    // Check collision with server's authoritative map
    int tileX = (int)(newX / TILE_SIZE);
    int tileY = (int)(newY / TILE_SIZE);
    
    if (level[tileY][tileX] == 0) { // Air tile
        client.x = newX;
        client.y = newY;
        // Server updates authoritative position
    }
    // Otherwise, request denied silently
}

4. Server Features
4.1 Vision System (Server-Side Ray Casting)
When client requests VISION_SCAN:
void handleVisionScan(ConnectedClient& client) {
    visibleEntities.clear();
    
    const float VISION_RADIUS = 160.0f; // 5 tiles
    
    for (int i = 0; i < 20; i++) {
        if (i == client.clientID) continue; // Don't see self
        
        float dx = players[i].x - client.x;
        float dy = players[i].y - client.y;
        float dist = sqrt(dx*dx + dy*dy);
        
        if (dist <= VISION_RADIUS) {
            // Check line-of-sight (no walls blocking)
            if (hasLineOfSight(client.x, client.y, players[i].x, players[i].y)) {
                visibleEntities.push_back({
                    .id = i,
                    .team = players[i].team,
                    .relX = (int)dx,
                    .relY = (int)dy,
                    .dist = (int)(dist / TILE_SIZE)
                });
            }
        }
    }
    
    // Client can now query visibleEntities via VISION_SELECT
}


Key: Server does expensive computation (line-of-sight), client just queries results.
4.2 Message Bus (Server Routes Messages)
struct Message {
    int fromID;
    int toID;
    int type;
    int data;
};


std::unordered_map<int, std::queue<Message>> inboxes;


void handleMessageSend(ConnectedClient& sender, int toID, int type, int data) {
    // Server validation
    if (toID < 0 || toID >= 20) return;        // Invalid recipient
    if (toID == sender.clientID) return;       // Can't message self
    if (inboxes[toID].size() >= 8) return;     // Inbox full
    
    // Server routes message
    inboxes[toID].push({
        .fromID = sender.clientID,
        .toID = toID,
        .type = type,
        .data = data
    });
}


Benefits:
* Server can log/monitor all messages (debugging)
* Server can filter/block messages (anti-cheat)
* Server can implement message delays (simulate network latency)
4.3 Dynamic Map Generation (Server-Side Only)
void updateDynamicMap() {
    mapChangeTimer--;
    
    if (mapChangeTimer <= 0) {
        mapChangeTimer = 900; // 15 seconds at 60 FPS
        
        // Cellular automata step
        for (int attempt = 0; attempt < 10; attempt++) {
            int x = rand() % 40;
            int y = rand() % 30;
            
            // Flip tile state
            int oldState = level[y][x];
            level[y][x] = (oldState == 0) ? 1 : 0;
            
            // Validate: ensure no client is trapped
            if (validateMapConnectivity()) {
                break; // Change accepted
            } else {
                level[y][x] = oldState; // Revert change
            }
        }
    }
}


bool validateMapConnectivity() {
    // Flood fill from each client position
    // Ensure all clients can reach open space
    // (Simplified connectivity check)
    for (auto& client : clients) {
        if (!canReachOpenSpace(client.x, client.y)) {
            return false; // This change traps a client
        }
    }
    return true;
}


Clients never see the map change directly - they just observe it through queries.

!main
    ldr rA, [CLIENT_TEAM]  ; My team


!loop
    ; Request vision scan from server
    set rB, 1
    str [VISION_SCAN], rB
    
    ; Check how many entities server returned
    ldr rC, [VISION_COUNT]
    cmp rC, 0
    je !no_enemies
    
    ; Find nearest enemy
    call !find_nearest_enemy
    ; rD now contains direction to move
    
    str [MOVE_REQUEST], rD
    jmp !end_turn


!no_enemies
    ; Random walk
    call !random_direction
    str [MOVE_REQUEST], rE


!end_turn
    set rF, 1
    str [CLIENT_YIELD], rF
    jmp !loop


!find_nearest_enemy
    set rG, 0              ; Index
    set rH, 999            ; Min distance
    set rI, 0xFF           ; Best direction
    
!scan_loop
    ; Query server for entity at index rG
    str [VISION_SELECT], rG
    ldr rJ, [VISION_TEAM]
    
    ; Is it an enemy?
    cmp rJ, rA
    je !same_team
    
    ; Get position
    ldr rK, [VISION_X]
    ldr rL, [VISION_Y]
    
    ; Calculate direction (simplified)
    call !calc_direction   ; Sets rD
    ret


!same_team
    inc rG
    ldr rC, [VISION_COUNT]
    cmp rG, rC
    jl !scan_loop
    ret


5.3 Team Coordinator Client
; TeamClient.asm - Communicates with teammates
.const CLIENT_ID        0x4000
.const CLIENT_TEAM      0x4001
.const MSG_INBOX_COUNT  0x4130
.const MSG_READ_IDX     0x4131
.const MSG_READ_TYPE    0x4133
.const MSG_READ_DATA    0x4134
.const MSG_SEND_TO      0x4120
.const MSG_SEND_TYPE    0x4121
.const MSG_SEND_DATA    0x4122
.const MSG_SEND_EXEC    0x4123


.const MSG_ENEMY_SPOTTED  0x01
.const MSG_HELP_REQUEST   0x02


!main
    ldr rA, [CLIENT_ID]
    ldr rB, [CLIENT_TEAM]


!loop
    ; Check inbox from server
    ldr rC, [MSG_INBOX_COUNT]
    cmp rC, 0
    je !no_messages
    
    ; Read first message
    set rD, 0
    str [MSG_READ_IDX], rD
    ldr rE, [MSG_READ_TYPE]
    
    cmp rE, MSG_ENEMY_SPOTTED
    je !handle_enemy_alert
    
!no_messages
    ; Scan for enemies
    call !scan_environment
    
    ; If enemy found, broadcast to team
    cmp rF, 0xFF
    je !no_broadcast
    
    ; Send message to all teammates
    call !broadcast_to_team
    
!no_broadcast
    call !make_move
    
    set rZ, 1
    str [CLIENT_YIELD], rZ
    jmp !loop


!broadcast_to_team
    ; Loop through team member IDs
    ; (Team 0: IDs 0-9, Team 1: IDs 10-19)
    cmp rB, 0
    je !team_red
    set rG, 10  ; Blue team start
    jmp !send_loop
    
!team_red
    set rG, 0   ; Red team start


!send_loop
    cmp rG, rA  ; Don't message self
    je !skip
    
    ; Send to teammate via server
    str [MSG_SEND_TO], rG
    set rH, MSG_ENEMY_SPOTTED
    str [MSG_SEND_TYPE], rH
    str [MSG_SEND_DATA], rF  ; Enemy position
    set rI, 1
    str [MSG_SEND_EXEC], rI


!skip
    inc rG
    ; Check if still in team range
    cmp rB, 0
    je !check_red
    cmp rG, 20
    jl !send_loop
    ret
    
!check_red
    cmp rG, 10
    jl !send_loop
    ret

6. Game Rules & Server Logic
6.1 Tag Mechanics (Server Authority)
void checkTaggingEvents() {
    for (int i = 0; i < 20; i++) {
        if (players[i].state != ACTIVE) continue;
        
        for (int j = 0; j < 20; j++) {
            if (i == j) continue;
            if (players[j].state != ACTIVE) continue;
            if (players[i].team == players[j].team) continue;
            
            float dx = players[i].x - players[j].x;
            float dy = players[i].y - players[j].y;
            float dist = sqrt(dx*dx + dy*dy);
            
            if (dist < 24.0f) { // TAG_DISTANCE
                // Server enforces tag
                handleTag(i, j);
            }
        }
    }
}


void handleTag(int tagger, int tagged) {
    // Update scores (server authority)
    if (players[tagger].team == 0) {
        redScore++;
    } else {
        blueScore++;
    }
    
    // Freeze tagged player
    players[tagged].state = FROZEN;
    players[tagged].freezeTimer = 180; // 3 seconds at 60 FPS
    
    // Respawn logic
    respawnPlayer(tagged);
    
    // Grant immunity
    players[tagged].state = IMMUNE;
    players[tagged].immunityTimer = 120; // 2 seconds
}


6.2 Spawn System (Server Managed)
void respawnPlayer(int clientID) {
    int team = players[clientID].team;
    
    // Team spawn zones (opposite corners)
    int spawnX, spawnY;
    if (team == 0) { // Red team: top-left
        spawnX = 2 + (rand() % 3); // Tiles 2-4
        spawnY = 2 + (rand() % 3);
    } else { // Blue team: bottom-right
        spawnX = 35 + (rand() % 3); // Tiles 35-37
        spawnY = 25 + (rand() % 3);
    }
    
    // Convert to pixels
    players[clientID].x = spawnX * TILE_SIZE + 8;
    players[clientID].y = spawnY * TILE_SIZE + 8;
    
    // If spawn blocked, try nearby tiles (server handles)
    if (level[spawnY][spawnX] != 0) {
        findNearestOpenTile(spawnX, spawnY);
    }
}

10. Key Design Decisions
10.1 Why Server Authority?
Server-authoritative design prevents:
* Clients cheating (teleporting, seeing through walls)
* Inconsistent world state (two clients occupying same space)
* Race conditions (clients modifying map simultaneously)
Trade-offs:
* More MMIO calls from clients (query overhead)
* Server must validate every action
* Clients can't cache world state reliably
10.2 Why Time-Slicing?
Alternatives considered:
* Event-driven: Clients wake up on events → Complex scheduling
* Real-time threads: Multiple VMs in parallel → TeenyAT doesn't support
* Turn-based: Strict ordering → Too slow, not multi-agent
Time-slicing wins because:
* Fair CPU distribution
* Simulates concurrent execution
* Simple to implement
* Allows varying CPU budgets (balance)
10.3 Why Message Passing?
Alternatives:
* Shared memory: Clients read global arrays → No isolation
* Broadcast: Server pushes updates → Not request-response
Message passing wins because:
* Explicit communication (easy to debug/log)
* Server can filter/monitor messages
* Teaches distributed systems concepts
* True multi-agent architecture

11.1 Bus Read Handler (Server Responses)
void bus_read(teenyat *t, tny_uword addr, tny_word *data, uint16_t *delay) {
    // Find which client is making this request
    ConnectedClient* client = findClientByVM(t);
    if (!client) {
        data->u = 0;
        return;
    }
    
    data->u = 0; // Default response
    
    switch(addr) {
        // === IDENTITY ===
        case CLIENT_ID:
            data->u = client->clientID;
            break;
            
        case CLIENT_TEAM:
            data->u = client->teamID;
            break;
            
        case CLIENT_X:
            data->u = (tny_uword)players[client->clientID].x;
            break;
            
        case CLIENT_Y:
            data->u = (tny_uword)players[client->clientID].y;
            break;
            
        case CLIENT_STATE:
            data->u = players[client->clientID].state;
            break;
            
        // === WORLD STATE ===
        case WORLD_TIME:
            data->u = gameTimer;
            break;
            
        case WORLD_RED_SCORE:
            data->u = redScore;
            break;
            
        case WORLD_BLUE_SCORE:
            data->u = blueScore;
            break;
            
        // === MAP QUERIES ===
        case MAP_RESULT: {
            int qx = client->mapQueryX;
            int qy = client->mapQueryY;
            
            // Server validates bounds
            if (qx < 0 || qx >= LEVEL_WIDTH || qy < 0 || qy >= LEVEL_HEIGHT) {
                data->u = 1; // Out of bounds = wall
            } else {
                data->u = level[qy][qx];
            }
            break;
        }
        
        // === VISION RESULTS ===
        case VISION_COUNT:
            data->u = client->visionResults.size();
            break;
            
        case VISION_ID: {
            int idx = client->visionSelectIndex;
            if (idx >= 0 && idx < client->visionResults.size()) {
                data->u = client->visionResults[idx].id;
            }
            break;
        }
        
        case VISION_TEAM: {
            int idx = client->visionSelectIndex;
            if (idx >= 0 && idx < client->visionResults.size()) {
                data->u = client->visionResults[idx].team;
            }
            break;
        }
        
        case VISION_X: {
            int idx = client->visionSelectIndex;
            if (idx >= 0 && idx < client->visionResults.size()) {
                data->s = client->visionResults[idx].relX; // Signed!
            }
            break;
        }
        
        case VISION_Y: {
            int idx = client->visionSelectIndex;
            if (idx >= 0 && idx < client->visionResults.size()) {
                data->s = client->visionResults[idx].relY; // Signed!
            }
            break;
        }
        
        case VISION_DIST: {
            int idx = client->visionSelectIndex;
            if (idx >= 0 && idx < client->visionResults.size()) {
                data->u = client->visionResults[idx].dist;
            }
            break;
        }
        
        // === TAG RESULT ===
        case TAG_RESULT:
            data->u = client->lastTagResult;
            break;
            
        // === MESSAGE INBOX ===
        case MSG_INBOX_COUNT:
            data->u = clientInboxes[client->clientID].size();
            break;
            
        case MSG_READ_FROM: {
            int idx = client->messageReadIndex;
            auto& inbox = clientInboxes[client->clientID];
            if (idx >= 0 && idx < inbox.size()) {
                data->u = inbox[idx].fromID;
            }
            break;
        }
        
        case MSG_READ_TYPE: {
            int idx = client->messageReadIndex;
            auto& inbox = clientInboxes[client->clientID];
            if (idx >= 0 && idx < inbox.size()) {
                data->u = inbox[idx].type;
            }
            break;
        }
        
        case MSG_READ_DATA: {
            int idx = client->messageReadIndex;
            auto& inbox = clientInboxes[client->clientID];
            if (idx >= 0 && idx < inbox.size()) {
                data->u = inbox[idx].data;
            }
            break;
        }
        
        default:
            // Unknown address
            break;
    }
}


11.2 Bus Write Handler (Server Request Processing)
void bus_write(teenyat *t, tny_uword addr, tny_word data, uint16_t *delay) {
    ConnectedClient* client = findClientByVM(t);
    if (!client) return;
    
    switch(addr) {
        // === MAP QUERIES ===
        case MAP_QUERY_X:
            client->mapQueryX = data.u;
            break;
            
        case MAP_QUERY_Y:
            client->mapQueryY = data.u;
            break;
            
        // === VISION SYSTEM ===
        case VISION_SCAN:
            if (data.u == 1) {
                performVisionScan(client);
            }
            break;
            
        case VISION_SELECT:
            client->visionSelectIndex = data.u;
            break;
            
        // === MOVEMENT ===
        case MOVE_REQUEST: {
            int dir = data.u % 8;
            processMovementRequest(client, dir);
            break;
        }
        
        // === TAGGING ===
        case TAG_REQUEST:
            client->tagTargetID = data.u;
            break;
            
        case TAG_RESULT: // Actually should be TAG_EXECUTE
            processTagAttempt(client, client->tagTargetID);
            break;
            
        // === MESSAGING ===
        case MSG_SEND_TO:
            client->msgSendTo = data.u;
            break;
            
        case MSG_SEND_TYPE:
            client->msgSendType = data.u;
            break;
            
        case MSG_SEND_DATA:
            client->msgSendData = data.u;
            break;
            
        case MSG_SEND_EXEC:
            if (data.u == 1) {
                sendMessage(client->clientID, client->msgSendTo, 
                           client->msgSendType, client->msgSendData);
            }
            break;
            
        case MSG_READ_IDX:
            client->messageReadIndex = data.u;
            break;
            
        case MSG_POP:
            if (data.u == 1 && !clientInboxes[client->clientID].empty()) {
                clientInboxes[client->clientID].pop_front();
            }
            break;
            
        // === CLIENT CONTROL ===
        case CLIENT_YIELD:
            if (data.u == 1) {
                client->state = YIELDED;
            }
            break;
            
        default:
            break;
    }
}


11.3 Vision Scan Implementation
struct VisionResult {
    int id;
    int team;
    int relX;
    int relY;
    int dist;
};


void performVisionScan(ConnectedClient* client) {
    client->visionResults.clear();
    
    const float VISION_RADIUS = 160.0f; // 5 tiles * 32 pixels
    
    int myID = client->clientID;
    float myX = players[myID].x;
    float myY = players[myID].y;
    
    // Check all other entities
    for (int i = 0; i < 20; i++) {
        if (i == myID) continue; // Can't see self
        
        float dx = players[i].x - myX;
        float dy = players[i].y - myY;
        float dist = sqrt(dx*dx + dy*dy);
        
        // Within vision radius?
        if (dist > VISION_RADIUS) continue;
        
        // Line-of-sight check (raycasting)
        if (!hasLineOfSight(myX, myY, players[i].x, players[i].y)) {
            continue; // Blocked by wall
        }
        
        // Add to visible entities
        client->visionResults.push_back({
            .id = i,
            .team = players[i].team,
            .relX = (int)dx,
            .relY = (int)dy,
            .dist = (int)(dist / TILE_SIZE)
        });
    }
    
    // Sort by distance (nearest first)
    std::sort(client->visionResults.begin(), client->visionResults.end(),
              [](const VisionResult& a, const VisionResult& b) {
                  return a.dist < b.dist;
              });
}


bool hasLineOfSight(float x1, float y1, float x2, float y2) {
    // Bresenham's line algorithm to check for walls
    int dx = abs((int)x2 - (int)x1);
    int dy = abs((int)y2 - (int)y1);
    int steps = max(dx, dy) / (TILE_SIZE / 2);
    
    for (int i = 0; i <= steps; i++) {
        float t = (float)i / steps;
        float x = x1 + t * (x2 - x1);
        float y = y1 + t * (y2 - y1);
        
        int tileX = (int)(x / TILE_SIZE);
        int tileY = (int)(y / TILE_SIZE);
        
        if (tileX < 0 || tileX >= LEVEL_WIDTH || 
            tileY < 0 || tileY >= LEVEL_HEIGHT) {
            return false; // Out of bounds
        }
        
        if (level[tileY][tileX] == 1) {
            return false; // Wall blocks vision
        }
    }
    
    return true;
}


11.4 Movement Processing
void processMovementRequest(ConnectedClient* client, int direction) {
    int id = client->clientID;
    
    // Check if client can move
    if (players[id].state == FROZEN) {
        return; // Frozen players can't move
    }
    
    // Calculate new position
    const float MOVE_SPEED = 3.0f;
    const int dx[8] = {1, 1, 0, -1, -1, -1, 0, 1};
    const int dy[8] = {0, 1, 1, 1, 0, -1, -1, -1};
    
    float newX = players[id].x + dx[direction] * MOVE_SPEED;
    float newY = players[id].y + dy[direction] * MOVE_SPEED;
    
    // Collision detection (server authority)
    int tileX = (int)(newX / TILE_SIZE);
    int tileY = (int)(newY / TILE_SIZE);
    
    // Bounds check
    if (tileX < 0 || tileX >= LEVEL_WIDTH || 
        tileY < 0 || tileY >= LEVEL_HEIGHT) {
        return; // Out of bounds
    }
    
    // Wall check
    if (level[tileY][tileX] == 1) {
        return; // Wall collision
    }
    
    // Check player collision (optional: prevent overlapping)
    for (int i = 0; i < 20; i++) {
        if (i == id) continue;
        
        float dx = newX - players[i].x;
        float dy = newY - players[i].y;
        float dist = sqrt(dx*dx + dy*dy);
        
        if (dist < 16.0f) { // Player size collision
            return; // Too close to another player
        }
    }
    
    // Movement approved by server
    players[id].x = newX;
    players[id].y = newY;
}


11.5 Tag Processing
void processTagAttempt(ConnectedClient* client, int targetID) {
    int taggerID = client->clientID;
    
    // Validate request
    if (targetID < 0 || targetID >= 20) {
        client->lastTagResult = 0;
        return;
    }
    
    if (players[taggerID].state != ACTIVE) {
        client->lastTagResult = 0;
        return;
    }
    
    if (players[targetID].state != ACTIVE) {
        client->lastTagResult = 0;
        return;
    }
    
    if (players[taggerID].team == players[targetID].team) {
        client->lastTagResult = 0; // Can't tag teammates
        return;
    }
    
    // Check distance
    float dx = players[taggerID].x - players[targetID].x;
    float dy = players[taggerID].y - players[targetID].y;
    float dist = sqrt(dx*dx + dy*dy);
    
    if (dist > 24.0f) { // TAG_DISTANCE
        client->lastTagResult = 0;
        return;
    }
    
    // TAG SUCCESSFUL!
    client->lastTagResult = 1;
    
    // Update score
    if (players[taggerID].team == 0) {
        redScore++;
    } else {
        blueScore++;
    }
    
    // Freeze and respawn target
    players[targetID].state = FROZEN;
    players[targetID].freezeTimer = 180; // 3 seconds
    respawnPlayer(targetID);
    
    // Grant immunity after respawn
    players[targetID].state = IMMUNE;
    players[targetID].immunityTimer = 120; // 2 seconds
    
    // Visual effect (optional)
    createTagParticles(players[targetID].x, players[targetID].y);
}

    jne !not_goal
    cmp rB, rD
    je !astar_success
    
!not_goal

    call !move_to_closed_list

    call !explore_neighbors
    
    jmp !astar_loop

!astar_failed

    ret

    cmp rE, 3

    jmp !neighbor_done


!check_east
    mov rF, rA
    inc rF                 ; neighbor_x = current_x + 1
    mov rG, rB             ; neighbor_y = current_y
    jmp !process_neighbor


!check_south
    mov rF, rA
    mov rG, rB
    inc rG
    jmp !process_neighbor


!check_west
    mov rF, rA
    dec rF
    mov rG, rB
    jmp !process_neighbor


!check_north
    mov rF, rA
    mov rG, rB
    dec rG
    ; Fall through to process_neighbor

    str [MAP_QUERY_X], rF

    for (int frame = 0; frame < frames; frame++) {
        updateAllClients();
        updateGameState();

        for (int i = 0; i < 20; i++) {
            assert(players[i].x >= 0);
            assert(players[i].x < SCREEN_WIDTH_PIXELS);
            assert(players[i].y >= 0);
            assert(players[i].y < SCREEN_HEIGHT_PIXELS);
        }
        
        // INVARIANT 2: Scores non-negative and monotonic
        static int lastRedScore = 0;
        static int lastBlueScore = 0;
        assert(redScore >= lastRedScore);
        assert(blueScore >= lastBlueScore);
        lastRedScore = redScore;
        lastBlueScore = blueScore;
        
        // INVARIANT 3: Message inbox sizes capped
        for (int i = 0; i < 20; i++) {
            assert(clientInboxes[i].size() <= 8);
        }
        
        // INVARIANT 4: No two active players at same position
        for (int i = 0; i < 20; i++) {
            if (players[i].state != ACTIVE) continue;
            for (int j = i + 1; j < 20; j++) {
                if (players[j].state != ACTIVE) continue;
                float dx = players[i].x - players[j].x;
                float dy = players[i].y - players[j].y;
                float dist = sqrt(dx*dx + dy*dy);
                assert(dist >= 1.0f); // At least 1 pixel apart
            }
        }
        
        // INVARIANT 5: Timer counts down properly
        static int lastTimer = 30000;
        assert(gameTimer <= lastTimer);
        lastTimer = gameTimer;
    }
    
    printf("  ✓ All invariants held for %d frames\n", frames);
}

Appendix: Build Instructions
Prerequisites
# Install TIGR dependencies (Linux)
sudo apt-get install libx11-dev libgl1-mesa-dev


# Or macOS
brew install glfw


Compilation
# Compile server
g++ -o main main.cpp tigr.c -lm -lGL -lX11 -std=c++17 -O2


# Assemble client programs (assuming you have TeenyAT assembler)
./tnyasm ChaseClient.asm -o ChaseClient.bin
./tnyasm TeamClient.asm -o TeamClient.bin
./tnyasm PatrolClient.asm -o PatrolClient.bin
./tnyasm AStarClient.asm -o AStarClient.bin


Running
# Run with default clients
./main


# Run with debug mode
./main --debug


# Run with custom client program
./main --client=MyCustomClient.bin --team=0


# Run tournament mode (load specific clients)
./main --red=ChaseClient.bin --blue=PatrolClient.bin


Configuration
Edit config.json:
{
  "cyclesPerFrame": 500,
  "visionRadius": 160,
  "tagDistance": 24,
  "gameDuration": 300,
  "mapChangeInterval": 15,
  "clients": [
    {"id": 0, "team": 0, "program": "ChaseClient.bin"},
    {"id": 1, "team": 0, "program": "ChaseClient.bin"},
    ...
  ]
}

Conclusion
This specification provides a complete, implementable design for a true multi-agent system built on TeenyAT, using a server-client architecture that:
1. ✅ Truly multi-agent: 20 independent VMs with isolation
2. ✅ Server authority: Single source of truth, validated requests
3. ✅ Realistic communication: MMIO protocol, message passing
4. ✅ Partial observability: Vision sensors, no omniscience
5. ✅ Emergent behavior: No central controller, coordination arises naturally
6. ✅ Extensible: Others can write new clients using documented API
7. ✅ Educational: Demonstrates distributed systems, AI algorithms, game architecture
